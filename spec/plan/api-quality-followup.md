### 残る原因・次の条件

1. nativeの不一致はLunaでSUBJECT/PREDICATE/PAYLOAD各3・QUOTE2・NOT_EXPECTED2、Claudeで前者各4・QUOTE2。
   同名群は両社7/10のまま。正規方向のcaller契約を、資料の意味と期待値の表現選択に分けて見直す必要がある。
   例えば同名群の「翻訳機能を受け持っているのは田中太郎さん」は人物→機能を期待する一方、新devの同型の担当者識別は機能→人物を期待する。
   現状のcatalogだけではこの選択が十分明確でない。名前やgroupで述語を変える処理、goldからのfocus注入は追加しない。
   catalogが異なる新devとの比較だけで既存goldの誤りを確定したものではない。raw非保存のため、上の具体例が今回の不一致を起こしたと特定してもいない。
2. `I-lifecycle-09`は1主張に2出典を要求する。現行のnative wireと公開候補はquote1個からdraft.evidence1個を作り、scoring.matchesは両出典の実際のevidenceを要求する。
   inputManifestは見た資料の依存記録であって引用根拠の代用ではない。この形式のまま当該期待値を満たせない。
   解消にはLLMが選んだ複数引用を既存の出典・Scope・byte検証で扱う契約設計が必要で、今回の固定公開契約の範囲では実装していない。
3. 旧独立の保持更新・実績数と上限の曖昧さは、正解の緩和で消さず未解決として保持する。
   非保存rawから元の誤りを再構成して再採点した扱いにはしない。新しい採点校正10/10で旧60例の合格は認定しない。
4. 40仕事の平文は評価30件で29〜30正解。完全正解のWorldでも改善上限1〜0件で、必要5件には届かない。
   平文の情報を減らす改変は行わない。構造の効果には別の事前固定集合での検証が必要だが、今回は予算がない。
   旧対照版の安全違反8回答枠も履歴に保持し、新版全armの再評価を省略して安全0へ変更しない。
