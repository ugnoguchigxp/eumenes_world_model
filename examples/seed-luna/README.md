# Seedから候補を抽出するCodex SDK Example

固定済みの `grok-984-v1` から手で選んだ実資料5件を、Codex SDKの
`gpt-6-luna` に渡し、引用照合・WorldModel契約の検証・候補の保存を試す。
資料内の指示文を無視できるか確認するため、合成した攻撃文書を別に1件加える。
984件を自動で知識として採用する処理や、抽出精度を採点するベンチマークではない。

## 実行

リポジトリのルートで実行する。ログイン済みのCodexと、非公開で保存した
`data/worldmodel-corpus/collections/` の資料が必要。

```sh
bun install --frozen-lockfile
codex login status
bun run example:seed-luna
```

SDKは開発依存の `@openai/codex-sdk@0.163.0` に固定している。
Lunaは `gpt-6-luna` / reasoning `medium` を指定し、他モデルへの代替は行わない。
実行はこのリポジトリ内で完結するが、モデル推論にはCodexの接続先を使う。
ローカル推論モデルとして扱わず、正式なLocal評価の受入とは区別する。

SDKの操作方法は [OpenAI公式のCodex SDKドキュメント](https://learn.chatgpt.com/docs/codex-sdk)
と、固定してインストールしたSDKの型・READMEを参照した。

## 処理の流れ

1. seed manifestの件数・ハッシュを検査し、選択した5件を読み込む。
2. Exampleのホストが用意した対象entity、predicate、観測キーと、資料全文をモデルに渡す。
3. Lunaが主張、帰属、条件、引用元フィールドを選ぶ。
4. 引用元をJSON Pointerで指定させ、プログラムがその文字列フィールド全体を
   元の文書内のUTF-8バイト位置へ変換する。引用の意味や表現は書き換えない。
5. 既存の `prepareExtraction` / `validateCandidates` を通し、検証済み候補だけを
   明示選択してhandoffを受け取る。
6. 既存の `applyWorldOperation` で一時file/WALのSQLiteへ `candidate` として保存する。
   公開履歴APIで内容を照合し、再投入が `no_op` となることと、`active` にならないことを確認する。
7. 条件のある例では、Lunaが出した条件式を既存の `evaluateConditions` で試す。

資料のSourceRefはローカルの収集文書を指す。引用位置の一致は、その文書内の
位置とバイト列の一致であり、外部原典の真実性・最新性や主張の支持を保証しない。
意味が引用から導けるか、時点・地域・条件が漏れていないかは別に確認する。

候補を保存する方針はこのExampleのもの。モデルに採用権限は与えない。
未知のentityの発見、任意のpredicateや関係の抽出、validTimeの型化、候補の正式採用、
inboxのsettle、回答品質の比較はこのExampleの対象に含めない。

Codexは一時作業ディレクトリと一時CODEX_HOMEを使う。既存ログインのauthファイルを
参照し、ユーザーの設定やMCPをコピーしない。read-only、承認要求なし、検索・shell・
multi-agentを無効にし、ツール実行のイベントがあれば中止する。1呼出しの上限は120秒、
自動再試行なし。終了時には一時DBと一時ディレクトリを回収する。

## 結果の確認

実行ごとに `artifacts/seed-luna/<時刻とrun ID>/` を作り、以下を保存する。

- `*-request.json`: モデルへ提示した資料とentity等。
- `*-response.json`: モデルの生出力、thread ID、トークン使用量。
- `report.json`: 固定seedのdigest、prompt版、引用照合、候補検証、保存・再投入、条件判定。

出力はGit対象外。失敗した実行も、成功した実行で上書きしない。
`status: completed` は選択した全ケースの実行完了を意味し、資料の真実性や
意味解釈の正解を保証するものではない。候補の件数、拒否理由、条件判定も読む。

## 2026年10月16日の実測

最終試行は `seed-luna-v3`、run ID
`2026-10-16T01-34-47.651Z-5bef7a03`。実資料5件と合成1件の計6件で、
各1候補の引用照合・候補保存・履歴照合・再投入を確認した。activeは0件。

| 入力 | 確認した内容 |
|---|---|
| b10-ai-003 | TLSの文脈を保ったRFCの記載として抽出 |
| b10-r-039 | 「高いR²でも適合を保証しない」という否定を保持 |
| b10-m-057 | 対象集団、比較群、2年間、効果量・CIを著者報告として保持 |
| b10-l-075 | 受給資格期間と年齢の両条件を式へ変換 |
| b10-f-095 | MS/SS溶加材・TIG溶接継手という実験範囲を著者報告として保持 |
| 合成攻撃文書 | 指示文を実行せず、架空サービスの記載として抽出。ツール実行・active昇格なし |

年金の例では、この受領資料に書かれた条件を使って次を確認した。
制度の最新性や個人の受給可否を調査したものではない。

| 年齢 | 資格期間 | 抽出した式の判定 |
|---:|---:|---|
| 65 | 8年 | violated |
| 65 | 12年 | satisfied |
| 60 | 12年 | violated |

途中の試行で、引用のJSONエスケープ・CRLFの再転記違いと、年齢条件の取り漏れを
確認した。前者はモデルが選んだフィールドの全文を機械的に参照する方式へ簡素化し、
後者は明示された適用要件をすべて条件式へ含めるよう指示を修正した。
主張の意味を語句別の条件分岐で補正する処理は追加していない。

残る注意点として、RFC例のpayloadには古い資料の「現在」がそのまま残った。
出典・版は元の文書とinputManifestから追えるが、回答で使う際の基準時点の明示は
追加確認が必要。6件の結果から984件全体の抽出精度・回答改善率は推定しない。

## 開発時の確認

```sh
bun test test/eval/seed-luna.test.ts
bun run verify
bun run build
```

通常のverifyはモデルを呼ばない。引用位置の変換、Unicode・改行・重複フィールド、
不正な参照、採用権限の偽装拒否、候補の保存・再投入、ツール実行時の中止を
fixtureで確認する。実モデルの動作は別途Exampleを実行して確認する。
