# 撤回済み規程の混入を減らす指示比較

**今回の比較で混入4件を0件に減らした。新規資料・未見設問では双方満点で差がなく、
既知の改善と未見での維持を確認した。補足指示は独立した候補として保存し、既存v5は維持する。**

事前の採用条件には「未見の主指標でペア改善数が悪化数を超える」を含めた。
ここは0対0で未達のため、優先候補・既定への採用は保留する。判定基準を後から変えない。

## 変更と原因の切り分け

実誤答では、撤回済みDS1はWorldの計算対象から外れ、DS2の評価と説明は正しかった。
それでもgoverningSourcesにDS1を追加した。計算基盤の撤回処理ではなく、履歴の説明で
参照する資料と、現在の判断に適用する資料の混同が疑われた。

候補は既存v5の末尾に、適用資料欄の意味を明確にする指示だけを追加する。
「今回有効な許可規程・観測方針の出典」を列挙し、説明中で過去の規程に言及しても、
そのことだけでは適用資料に含めない。同格の併存規程、施行前の旧規程、旧文書の
有効な観測章は保持する。入力・schema・判定・計算は共通。

資料の削除、回答の後処理、資料名や文言による判定はコードへ追加していない。
撤回済みの原文は両方式に残り、schemaでもそのIDを許す。適用の意味判断はLLMが行う。

## 比較結果

既知8問と新規4資料群16問、各2反復・2方式で96回答。新規抽出4回は両方式で共有。
同じモデル・medium、2並行、方式の順序を反転。指示・入力・期待値・コードを実行前に固定。

| 指標 | 基準v5 | 補足指示あり |
|---|---:|---:|
| 回答完了 | 48/48 | 48/48 |
| 判定正解 | 48/48 | 48/48 |
| 適用資料集合 | 44/48 | 48/48 |
| 許可規程評価の集合・結果 | 48/48 | 48/48 |
| 主指標（上記＋既存監査） | 44/48 | 48/48 |
| 既知群の主指標 | 12/16 | 16/16 |
| 未見群の主指標 | 32/32 | 32/32 |
| 撤回済み専用資料の混入 | 4/20 | 0/20 |
| 誤許可 | 0/32 | 0/32 |

混入の分母20は、その設問で撤回済み専用資料が存在する回答セル。旧文書の観測章が
有効な場合は混入と数えない。誤許可の分母32は本来allow以外のセル。

基準v5の誤りはDS02とNR01の各2反復。4件は独立した4設問ではない。いずれもDS1が
余分に列挙され、候補ではDS2だけになった。判定・許可規程評価・説明を壊さず回復した。
全体のペア改善4・悪化0・双方正解44、未回答0。既存の参照・転記・自己整合の監査は
基準v5の誤答も通過するため、適用資料集合を独立の期待値で採点した。

未見群では、連続改訂・施行境界、別区域の旧規程の存続、同格規程の併存、許可章だけ
撤回され観測章が残る文書を扱った。旧文書の観測章が必要なケースは両方式で全問成功。
「古い資料を消せばよい」という実装は、このケースを壊すことも回帰試験で確認した。

## 説明・抽出・費用の確認

全96説明をCodexが点検した（独立・盲検の評価ではない）。観測値・閾値・施行日・計算の
明確な事実誤認は未検出。候補CP02の両反復は匿名化の観測欠落にも言及しているが、
個人情報=falseなので匿名化は決定的な不足ではなく、公開猶予中の欠落が決定的である。
事実としての欠落は正しいものの、説明の焦点には改善余地がある。採点は変更しない。

新規抽出ではKB4/KB8/KB6の開始日が原文にあるのにvalidFromがnullだった。今回の
当該設問はすべて施行後なので期待計算に影響しないが、施行前の精度は評価できない。
SP2は許可章終了時にWorld主張全体が撤回され、存続する観測章は保持した原文から
参照される。本実験を「章単位の有効期間管理が実装済み」とは扱わない。

回答出力tokensは8,335→8,623（約3.5%増）、入力tokensは758,984→776,065。
平均回答時間は12.70→12.89秒。小規模で実行時の変動もあるため速度差を結論にしない。
合計100モデル呼出し（抽出4＋回答96）、通信失敗・再抽選なし。

## 検証と残したもの

- 部分試験で既知4種類の混入を再現し、SQLiteで元の入力を再構築。
- 全48ペアのrequestがバイト一致。差はdeveloper指示への補足だけ。正解・退役ID注釈は非提示。
- 28件の規程評価が期待値に一致し、全原文を保持。173コードdigest不変で実行完了。
- 全回答のdecision最終項目、全初回生応答・失敗・コストを記録。
- 100キャッシュの再生で追加呼出し0。report/eventsのdigest不変。
- 実測の成功・失敗ペアと、旧文書を一括除外すると誤るケースを回帰試験へ保存。

同名JSONにprotocol、生応答、採点、採用条件の成否、当時の実験コード、照合結果を保存。
通常verifyはモデルを呼ばない。最終verify/build結果はspec/plan/progress.mdに記載。
実行記録は `artifacts/operative-sources-comparison/2026-10-16T05-50-32.196Z-17c00fb8`。

今回の証拠は、指示の定義を補うことで既知の混入を抑え、未見群でも正解を維持したこと。
未見での相対優位、実資料への一般化、独立した評価者による再現はまだ確認できていない。
同じ設問の再抽選で差を作らず、改善が観測された指示と限界を併記して残す。
