## 作業範囲と完了条件

新Example・回帰試験・結果記録が対象。既存v5、本体src、公開契約、DB schema、
隣接repoは変更しない。新依存、資料の意味を分類するコード、回答の自動修正を追加しない。
意味判断はLLM、コードは既存の入出力・SQLite・条件計算・採点を再利用する。

1. 既知誤答4種類の再現。判定・計算照合が成功しても資料集合が誤ることを確認する。
2. 部分試験→SQLite再構築で元の入力を再現し、既存v5と候補の入力/schema一致を確認。
3. 資料・未見設問・期待値・指示・採用条件を固定し、実モデルで比較する。
4. 初回失敗を含む結果と説明を点検し、キャッシュ再生で結果不変を確認する。
5. verify/build、差分点検、結果記録、commit/pushで完了。失敗を消す再抽選や採点緩和はしない。

## 比較設計

既知8問（撤回混入4問＋許可規程/補助資料混同の回帰4問）、未見4資料群16問。
各2反復・2方式で96回答。新規抽出4回は両方式で共有。入力・schemaは同一で、
候補だけにprotocol.tsのsupplementを追加する。2並行、設問/反復ごとに方式順を反転。
抽出失敗は資料群の未回答として分母に残し、別の回復方式を途中で混ぜない。

未見条件: 多段の改訂と施行境界、別区域の旧規程が存続、同格の新旧規程が併存、
許可章だけ撤回して観測章が存続する文書。新しい名称・原文・観測条件を使う。
Mixed文書で旧IDが残るのは正解の場合があるため、単純なID禁止はしない。
retiredOnlySourcesは採点専用の事前期待値で、モデル入力・schemaには渡さない。

主指標: 判定・適用資料集合・許可規程評価の集合/結果・既存監査の全一致。
採用条件: 未見の主指標のペア改善数が悪化数を超える、既知主指標と両群の判定正解数を
下げない、新たな誤許可なし、候補の撤回済み専用資料の混入0、mixed文書4問の両反復が
主指標成功。引分けは改善未証明。採用可能でも既存v5を自動で置換しない。
説明文は別途点検し、機械監査と意味的な正しさを混同しない。

## 実行

```sh
bun test ./test/eval/operative-sources.test.ts ./test/eval/operative-sources-measured.test.ts
bun run verify
bun run build
bun examples/operative-sources-comparison/main.ts --prepare-only
bun <run>/frozen-code/examples/operative-sources-comparison/main.ts --resume <run>
```

通常verifyはモデルを呼ばない。コード・期待値・指示はprotocolとfrozen-codeに保存する。
実行中に編集しない。最大4抽出＋96回答、各SDK呼出し120秒、アプリ側の再試行なし。
成功・失敗の初回キャッシュを保持し、resumeは新しいサンプルへ置き換えない。
合成資料による同一作成者の評価で、実資料受入・独立盲検・統計的な一般化の証明ではない。
