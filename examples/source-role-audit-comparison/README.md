# 適用資料の役割を独立に確認する監査比較

v5・本体・既存監査・抽出・計算・採点・過去実験は維持する。対象は、DT04で対象外規程DT2を適用資料欄に追加しても監査が通る問題。許可評価への参照がない資料を一律に除くと、必要な観測章も失うため、意味の判断はLLMに委ねる。

## 実測結果

[2026-10-16の結果](../../fixtures/experiments/source-role-audit-comparison/2026-10-16.md): 61呼出し・90結果を取得。DT04は2反復中1回だけ検出・修復し、未見は全方式23/24正解で改善なし。必要な観測章は保持できたが、対象外資料の見逃しが残り、候補は不採用。v5を維持し、比較・再現資産として保存した。以下の採否条件は実測前に固定している。

## 実測前の固定計画

別のモデル呼出しに、元の原文・設問・時刻・観測・World計算と、適用資料IDの一覧だけを渡す。回答の説明・判定・評価は渡さず、各資料が今回の許可・制約・観測方法に適用されるか、背景説明だけかを確認する。モデルはapplicable/inapplicable/uncertain、役割、短い理由、原文の引用を返す。コードは全IDの重複なし網羅・引用先・逐語一致を検査し、意味を分類しない。引用一致は判断の正しさを保証しない。uncertainや契約不正を合格として扱わない。

同じ初回v5からbaseline（保持）、control（監査フィードバックなし見直し）、role（指摘付き見直し）を比較。control/roleは初回の役割監査を共有し、旧構造監査または役割監査が不合格なら1回見直す。同じ指示・schema・原文・元回答で、roleだけ役割監査を受け取る。修正後は双方に新規の役割監査を実施し、controlのacceptedは旧監査、roleは両監査の合格とする。合格初回は文字列不変。これは旧挙動そのままのcontrolではなく、見直し機会を揃える比較。合格と正答は別に計測し、拒否を正答に数えない。

既知3保存回答はDT04/0の対象外混入、DT04/1の正解、観測章の存続が正しいVT05。各2反復。新規3資料群8文書12問×2反復は区画・運転方式・章の存続/対象外、許可・不許可・保留を含む。合計30結果/方式、90セル。各群1抽出、初回共有、全原文を保持、正解非提示。3抽出＋24初回＋30初回監査＋最大60見直し＋60最終監査＝177呼出し上限、2並行、各120秒。方式順は反復で反転。抽出・通信再試行、2回目の修正、初回への差替えはしない。

部分→SQLite結合→verify/build後にコード・資料・設問・期待値・指示・採否を固定して実モデル実行。抽出拒否・監査契約不正・通信失敗も予定分母に残す。全生応答と説明/監査の意味を点検し、追加呼出し0で再生、SQLite・全分岐・費用・採点・採否を回帰試験で再現する。記録・全体検証・差分点検・commit/pushで完了。

採用条件はprotocol/adoptionに固定。監査は全件取得、DT04両反復検出、期待資料に対する誤警告/正解出力の拒否0、未見の旧監査見逃しを1件以上新規検出。修復採用はさらにDT04両反復修復、初回正解/判定保持、新たな誤許可/撤回混入なし、正しい観測資料保持、未見で純改善かつ2資料群以上改善。フィードバック優位は未見controlより純改善しcontrolの正解を壊さないこと。同点は優位と呼ばない。未達は比較資産としてのみ保存し、v5は既定のまま。

主指標は従来の判定・適用資料集合・許可評価集合/結果・旧監査の全一致。資料単位の期待集合との照合は実測後の採点に限る。適用資料の欠落や説明文の真偽は役割監査の保証外。合成資料・同一作成者・非独立非盲検で、実資料の受入ではない。モデル監査自身も誤る可能性を記録する。
