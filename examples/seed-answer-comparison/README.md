# seedの有無によるLuna回答の比較

12問×2反復×3条件で、Codex SDKの `gpt-6-luna` / mediumを使って72回答を取得する。
質問・期待する内容・採点指示は `protocol.ts` に実行前に定義し、実行時にファイルの
ハッシュも含めて `protocol.json` へ固定する。通常のverifyではモデルを呼ばない。

| 条件 | 回答モデルへ渡す材料 |
|---|---|
| no-seed | 共通の質問・シナリオの事実。資料なし。事前知識で回答可能 |
| raw-seed | 共通入力＋関連するseed資料の全文 |
| world-seed | raw-seedと同じ資料全文＋WorldModelのSlice・条件式の評価結果 |

出典ID、原文、質問、シナリオの年齢等は、対応する条件間で同じものを使う。
WorldModel側にだけ別の出典や正解を追加しない。原文を提示する2条件の差は、
抽出・構造化・条件評価を含む整理結果の追加である。抽出の要約効果と構造の効果を
この3条件だけでさらに分離することはできない。

## 実行

前の [抽出Example](../seed-luna/README.md) の、完走した `seed-luna-v3` の実モデル出力を
明示して使う。抽出結果を固定することで、回答比較へ抽出の揺れを混ぜない。

```sh
bun run example:seed-compare \
  --extraction-run artifacts/seed-luna/2026-10-16T01-34-47.651Z-5bef7a03
```

`--repeats 1|2|3` で反復数を指定できる。既定は2。
`--prepare-only` は固定seed照合、抽出の再検証、実SQLiteへの保存、12問分の
文脈生成までを行い、モデルを呼ばない。結果のstatusもモデル未実行と表示する。

実行先は `artifacts/seed-answer-comparison/<時刻とID>/`。`protocol.json`、文脈、
全回答・採点の生出力と使用量、呼出しの開始・終了・失敗ログ、`report.json` を残す。
途中で失敗した場合は成功した呼出しを保存し、次で未完了分から再開できる。

```sh
bun run example:seed-compare \
  --extraction-run artifacts/seed-luna/2026-10-16T01-34-47.651Z-5bef7a03 \
  --resume artifacts/seed-answer-comparison/<再開する実行のID>
```

再開時は、モデル・指示・rubric・反復数・ソース・抽出結果・コードのハッシュが
一致することを検査する。異なる条件の結果は混ぜない。設定変更は新しい実行とする。
SDKが提供していないsampling seed・temperatureを設定済みとは扱わない。
呼出しは逐次、各120秒まで、自動のモデル代替なし。

## WorldModelで実際に通す処理

984件の固定コーパスから、AI・研究・医療・生活・製造の5資料を使う。
Lunaが前の試験で作った候補を現在の資料へ再検証し、既存の公開APIで一時SQLiteへ
保存する。公開snapshot API→`buildWorldSlice`→`evaluateConditions` を通す。
文脈は毎回focusを限定し、予算切れや不完全なSliceはエラーにする。

候補はcandidateのままで、activeへ昇格しない。freshnessがunknownであることや
著者報告の由来も保持する。年齢等の観測は人が定義した試験シナリオであり、
自然文からの観測抽出を実装・評価したわけではない。

資料選択は人が関連する1件を指定する方式で、検索の精度は評価しない。
984件をすべて読み込んで照合するが、回答へ使う実資料は5件に限定する。
元の主張の真実性・最新性の原典調査や、ユーザー個人の医療・年金判断は行わない。

## 比較方法

- 質問は、既知の一般原則、数値の取得、適用範囲、条件の充足、欠けた情報、
  過去の情報を現在へ適用する危険を含む12問。元資料は5件なので独立した12資料とは数えない。
- 回答の指示・モデル・reasoningは全条件共通。各回答は新しいスレッドで作る。
  期待内容、採点指示、質問ID、条件名は回答モデルへ渡さない。
- 条件の実行順は均等に入れ替える。72回答とは別に、24回の採点呼出しを行う。
- 採点は別スレッドのLunaが、条件名を伏せたA/B/Cの3回答を、凍結した期待内容と
  同じ原典に照らして行う。ラベルの対応は回答の順とは別に入れ替え、対応表はホストだけが持つ。
- 正確さ、充足度、条件・適用範囲、不確実性の扱いを各0〜2点、計8点で集計する。
  正しい保留は正確さ・不確実性では高評価になり得るが、必要な数値を答えなければ
  充足度は低くなる。引用がないことだけを意味品質の減点理由にしない。
- 引用IDの存在、引用付き回答数、時間、入力・出力tokenは別に集計する。
  引用IDの一致は内容を支持する証明ではない。
- 同じ問・反復の組で比較する。1軸でも悪化ならworse、悪化せず得点が増えればimproved、
  全軸同じならsame。採点の不確実性があればincomparableとし、比較可能数を明示する。

同じモデルによる採点には偏りがあり、引用や表現から条件を推測できる可能性もある。
生回答と理由を人が確認して、評価器の採点と独立した確認を区別して記録する。
小標本で反復も同じ質問・出典を共有するため、統計的有意性や984件全体の改善率は主張しない。
この実験は正式なLocalモデルの受入・P5評価の完了とも区別する。

前回の抽出Exampleで調整した年齢条件と重なる設問もあり、未知のholdout試験ではない。

## 2026年10月16日の結果

run IDは `2026-10-16T02-05-02.865Z-158c5f3a`。
72回答・24組の採点を完走した。最初の採点に120秒のタイムアウトが1回あり、
成功済みの3回答を再生成せず再開した。

**資料に固有の数値を答える効果は確認できた。資料だけに対してWorldModelの整理結果を
追加する効果は、この問題集合では確認できなかった。**

| 論文の具体値を求めた2問×2回 | 必要な値を正しく回答 | 数値の誤り | 数値が分からず保留 |
|---|---:|---:|---:|
| seedなし | 0/4 | 1/4 | 3/4 |
| 資料のみ | 4/4 | 0/4 | 0/4 |
| 同じ資料＋WorldModel | 4/4 | 0/4 | 0/4 |

保留は捏造を避けた適切な挙動だが、必要な数値は得られていない。
一般原則・適用範囲・年齢条件などの質問は、seedなしでも概ね適切に答えていた。
WorldModelを加えた回答は不足している年齢条件へ焦点を絞る傾向があったが、
資料のみとの全24組の自動採点は同点だった。資料提示時点で満点に達する天井もあり、
他の難しい仕事で差がないという結論にはしない。

### 採点器の問題と監査

初回採点は、資料のない回答者の正当な保留を誤答として減点した。
元の回答、質問、期待内容、元の採点を残し、採点器に回答者が実際に見た出典IDを明示して
全24組を再確認した。条件名は伏せ、回答者に提示された出典IDだけを開示した。
Raw/Worldを区別する条件名やWorldSlice自体は採点器へ渡していない。
これは結果確認後の採点指示の修正であり、事後監査と明記する。

```sh
bun examples/seed-answer-comparison/audit.ts \
  --run artifacts/seed-answer-comparison/<完走した実行のID>
```

監査にも `--resume <監査の実行先>` がある。元のreportのハッシュ・指示・
キャッシュ済み要求の一致を検査して、生出力を再利用する。

| 条件 | 初回平均/8 | 監査後平均/8（参考） | 平均回答時間 | 平均入力token |
|---|---:|---:|---:|---:|
| seedなし | 6.58 | 7.29 | 6.70秒 | 13,501 |
| 資料のみ | 8.00 | 8.00 | 6.61秒 | 14,985 |
| 同じ資料＋WorldModel | 8.00 | 8.00 | 6.37秒 | 15,580 |

監査後でも、質問していない数値の欠落などを減点する偏りが一部残った。
点数を都合よく手修正していない。得点差を精度の確定的な改善幅とはせず、
具体値の照合と生回答の比較を主な証拠とする。監査でRaw/World対seedなしは
8組改善・16組同点、World対Rawは24組すべて同点だったが、この件数も採点器依存の参考値。

判明した3件の「妥当な保留を誤答扱いしない」という採点回帰ケースを
`grader-regressions.json` に追加した。親reportのハッシュに固定しており、回答を
再生成した別実行へは適用しない。実際の監査出力は3件すべて基準を満たした。

```sh
bun examples/seed-answer-comparison/check-grader.ts \
  --audit artifacts/seed-answer-comparison/<実行ID>/<監査ID>/report.json
```

全回答の対照とCodexによる定性的確認は、その実行先の `comparison.md` と
`codex-review.json` に保存した。独立した人手評価ではない。
同じ資料＋WorldModelは資料のみより平均入力tokenが約4.0%増えた。
今回の近い応答時間から速度差の有意性は主張しない。採点時間と失敗した採点は
平均回答時間に含めず、失敗時のtoken使用量は不明として残す。
