# 適用規程と計算結果を対応付けた回答の未見比較

既存のv4を調整せず、新しく作成した8資料群・32問で従来方式と比較する。
同じ原文、実モデルの抽出、SQLiteで保存・投影したSlice、条件計算を両者へ渡す。
資料群の名称だけでなく、条件の組合せ、適用範囲、時点、観測も新規作成した。
既知の失敗から検証カテゴリを選んだ合成評価であり、独立の人手評価や実仕事での受入ではない。

| 条件 | 提示と回答 |
|---|---|
| legacy | v2の指示・判定先行schema。Sliceと計算結果を別配列で提示 |
| linked | 完了済みv4の指示・schema。規程ごとに計算を結合し、根拠記録、説明、最終判定の順で回答 |

v2の指示から旧fixture専用のO2に関する一文だけを外した。v4の指示は完了runからそのまま固定。
現在の共有コードにはv5の原子条件検査もあるが、今回はv4の引数で呼び、追加情報を渡さない。
旧v4の全16問について、実際の要求文・schemaを完全一致で再現できることをモデルなしで確認した。
新しいデータによる結果を見て指示・期待値を変更しない。

比較するのは指示・出力schema・提示方法の組全体であり、提示方法だけの効果ではない。
原文・計算は同じなので、全文のみとの比較や条件計算自体の有効性とは区別する。

## 固定する設計

- 8資料群×4問×2反復×2条件＝128回答、共通の抽出8呼出し。最大136呼出し。
- 2並行、各対応ペアの順序は反復で反転。毎回独立したSDK会話。モデルはgpt-6-luna / medium。
- 既存のSDK隔離、引用検査、候補検証、公開SQLite API、条件計算、根拠監査を再利用。
- 抽出へ質問・正解を渡さない。回答にも期待判定や期待する適用規程を渡さない。
- すべてcandidateのまま。適用する規程・権威・意味の判断はモデルが担う。
- 各呼出し120秒、自動再試行・回答修正・別モデルへの代替なし。失敗も固定し、再開で再生成しない。
- 主指標は最初の生回答の判定一致。根拠集合、誤許可、正しい許可・保留、使用量、時間を別集計。
- linkedでは転記と自己整合に加え、事前に定めた適用規程の網羅・結果を別採点する。
  正しく転記しただけでは資料選択や説明が正しいとはしない。
- すべての説明を別途読み、判定点を書き換えず問題を残す。
- 2反復や同じ資料群の設問を独立標本とはしない。資料群別結果も記録する。

計算の要約と観測値の区別、ORで補える欠落、否定の中のunknown、施行時刻、
同格規程の競合、単位不一致、同順位の観測衝突、鮮度境界、未来の観測、
対象外の規程、権限のない文書中の指示を含む。

「効果あり」は対応比較で改善し、誤許可が増えない場合に限定する。
同点なら追加効果未確認とする。失敗0件でも一般的な安全性は保証しない。
構造監査の合格率と説明の正しさ、実験の完走と品質の合格は別である。

## 実行

```sh
bun test test/eval/linked-answer-holdout.test.ts
bun run verify
bun run build
bun examples/linked-answer-holdout/main.ts --prepare-only
```

準備で表示された絶対パスを `<run>` として、保存したコードから実行する。
準備後に共有ファイルが変わっても実行中の比較へ混ざらない。

```sh
bun <run>/frozen-code/examples/linked-answer-holdout/main.ts --resume <run>
bun examples/linked-answer-holdout/render.ts --run <run>
```

元の作業ツリーからの再開は、全コードdigestが一致する場合だけ可能。
保存されたコード・資料・指示・採点が異なると再開を拒否する。
コードの凍結はモデルのサービス側の更新まで固定するものではない。

出力は `artifacts/linked-answer-holdout/<run>/`。
protocol、frozen-code、生要求・応答、失敗、SQLite履歴とcontext、report、eventsを保存する。
初回抽出の使用量と回答使用量は別。キャッシュから再開した際の新規呼出し数は標準出力へ記録する。
通常のverifyは実モデルを呼ばない。

## 変更範囲

この新しいExampleとfixture試験、文書・進捗記録。本体src、公開契約、migration、
既存v4/v5の実装・結果、実資料984件、兄弟プロジェクトは変更しない。

部分検証で比較入力の一致、正解非提示、採点の不正検出、失敗を含む分母を確認し、
既存の結合試験を含む全体verifyの後に実モデル比較を行う。実行後は全キャッシュで再開し、
追加モデル呼出し0とreport/events不変を確認する。失敗を品質成功へ変えず、原因と未完了範囲を残す。
