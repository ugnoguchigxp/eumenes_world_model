以下は実行前に固定した計画。採否条件は実測後に変更していない。

どちらも原文は入力にあり、PC01は正しいvalidFromとCLAIM_NOT_VALIDも受け取っていた。
CV04は既存監査で検出できるが、PC01は計算転記が合うため監査を通過した。

## 変更範囲と仮説

既存v5、前回の補足指示、World本体・公開契約・DB・抽出・採点は維持する。
新候補はv5の回答順序の段落だけを置換し、適用時点・範囲を確認してから条件計算を使う指示と、
assessments→governingSources→explanation→decisionの順序を与える。
資料欄には評価した全規程と有効な観測方針の両方を含めるよう指示する。
schemaの項目・値域・制約は同じで、出力順だけを変更する。説明のための隠れた推論は要求しない。

これは指示と順序を組にした比較であり、順序だけの寄与を分離する試験ではない。
CLAIM_NOT_VALIDは既存計算契約の説明に使い、コードで資料を選別しない。入力の原文や将来規程の計算も全方式に残す。
資料ID・特定語句の専用分岐、自動修正、再回答による救済、新たな依存や実行基盤は追加しない。

## 固定する比較条件と採用条件

- 3方式: baseline=既存v5、operative=前回の補足指示をそのまま、applicability=新候補。
- 既知8問: PC01/CV04、前回改善AR03/NR02/CP02、資料役割O04/AC04、併存規程RP02。
- 未見4資料群14文書16問: 正午の施行1 ms前/ちょうどと多段改訂、観測章だけ存続、両章撤回して別々の新文書へ置換、範囲別の旧規程存続。
- 各2反復で144回答＋4抽出。6通りの方式順を各8回使用、2並行。原文・観測・計算・設問は共通。
- 新規抽出は1回だけで共有する。失敗は全方式の分母に残し、再抽選・回復方式の途中追加はしない。
- 指示・schema・期待値・採否・コードを実行前に固定する。実行中の編集はしない。

主指標は判定・適用資料集合・許可規程評価の集合/結果・既存監査の全一致。採点は前回と同じ。
**改善候補として保持する条件**: 全呼出し完了、PC01/CV04と未見16問が両反復とも主指標正解、
各群の主指標と判定正解数がv5/前回指示の両方以上、候補の誤許可と撤回済み資料混入0、
今回の同時比較で少なくとも一方に対するペア改善数が悪化数を超えること。
**優先候補とする追加条件**: 未見でもv5に対するペア改善数が悪化数を超えること。
過去の失敗からの回復や未見での同点だけを、今回のv5への優位と呼ばない。既定v5は常に維持する。
