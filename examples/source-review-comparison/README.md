既知見逃しは通常見直し・重点指示とも2/2修正。未見の回答あり24件では主指標18→23/22、別の8件は抽出で未評価。
通常見直しが今回最良だが、未見の整合した誤答1件は両方式とも残った。重点指示は通常見直しに1件劣り、新規推奨にしない。
[結果・採否・中断runの扱い](../../fixtures/experiments/source-review-comparison/2026-10-16.md)を参照。以下は実測前に固定した計画と、設定不備の訂正記録。

既存v5、本体src、構造監査、抽出・計算・採点、過去の実験を変更しない。
目的は、誤った規程を選んだまま評価・説明・判定が一致すると監査を通る失敗を減らすこと。
意味判断はLLMに委ね、コードは呼出し上限、入出力契約、保存・再現を担う。

## 実測前に固定する計画

同じ初回回答から以下の3方式を比較する。

- baseline: 既存v5の初回回答を保持する。
- control: 前回の汎用見直し指示で、原資料・初回回答・既存監査結果を渡して必ず1回見直す。
- selection: controlと同じ入力・出力schema・回答順序・呼出し回数で、規程選択を原文から再確認する補足指示だけを追加する。

監査合格時も見直す。候補は権限、施行時点、対象範囲、置換範囲、並存規程、存続する観測章を原文から確認する。
前回答・計算結果・lifecycle・公表順を適用根拠として追認しない。正しい回答の改悪も計測する。
既存監査を再度実行し、合格だけをacceptedとするが、これは意味上の正しさや公開許可ではない。
再見直し、通信・抽出の再試行、失敗時の初回への置換、資料ID分岐、期待値による発動はしない。
通常見直しとの差は補足指示だけで、入力の監査結果は両方に渡す。呼出し順は反復ごとに逆転する。

既知は前回KR07（施行前の別規程を一貫して選んだ見逃し）とKR08（正しい回答）の保存済み初回2件を各2反復。
これは新規v5生成ではなく、意図的に選んだ固定回答の修正試験である。
未見は新規4資料群14文書16問×2反復。クレーンの施行境界、搬送台の観測章存続、台車の対象範囲、貯槽弁の同権限並存を含む。
抽出は資料群ごと1回、全方式で同じSQLite入力・初回回答を共有。原文と計算は全て保持し、期待値は渡さない。
既知4＋未見32＝36結果/方式、108セル。最大108呼出し＝4抽出＋32初回＋72見直し。2並行、各120秒。
資料抽出の拒否や通信失敗も全方式の予定分母に残す。実行中に指示・期待値・コードを変えない。

主指標は判定・適用資料集合・許可評価集合/結果・構造監査の全一致。
候補保持の条件は、全セル完了、既知見逃しを両反復で修正、正解だった初回の主指標/判定を改悪せず誤許可/撤回混入を新設しない、未見で純改善かつ2資料群以上で純改善。
controlより優先するには、さらに未見の対比較で純改善し、controlの正しい主指標/判定を壊さないこと。
既知だけの改善や同点は未見への効果・補足指示固有の効果とは言わない。採否にかかわらずv5は維持する。

## 必要作業と完了条件

1. 既知見逃しと旧方式の不発動、合格時見直し、1回上限、失敗保持、正解非提示を部分試験。
2. 既存SQLite結合試験と全体verify/build後、資料・指示・期待値・採否・実行コードを固定して実測。
3. 抽出・全回答・説明・費用を確認。追加呼出し0の再生とSQLite再構築、採点・全分岐の再現試験を追加。
4. 採否と限界を結果・進捗へ記録。全体verify/build、無関係差分と意味判断代替がないことを点検しcommit・push。

同じ作成者による合成資料であり、独立盲検・実資料での受入ではない。2反復は独立した2設問ではない。
