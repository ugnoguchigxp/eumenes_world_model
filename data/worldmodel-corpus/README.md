# WorldModel 実資料コーパス

WorldModelで知識を抽出・評価するための収集資料を置く。収集ツールは
`grokbot/`、合成評価データは `eval/` が所有し、この場所は実資料を所有する。
製品DBへの登録済み主張とは区別する。

## 保存単位

`collections/<受領日>-<収集元とバッチ名>/` を一つの受領・登録単位とする。

- `incoming/`: 受領したJSONLなどの原本。書き換えずに保持する。
- `accepted.jsonl`: レビューまたはユーザーの明示指示で登録した抽出用資料。
- `pending.jsonl`: 修正または確認を待つ資料。
- `reviews.jsonl`: レビューを実施した場合の点数、判断、使用範囲、根拠の制約。
- `manifest.json`: 入出力ハッシュ、件数、採用範囲、取得本文の有無。
- `review.md`: 採点基準、指摘と原典へのリンク。
- `judgments.json`: 評価者が付けた項目別評点と所見。
- `integrity.json`: 受領JSONL内の機械的整合性検査。
- `source-map.json`と`refetched/`: 再取得を行った場合のURL・ハッシュ・保存先・照合結果。

採用行の本文は原本と同じに保つ。修正が届いた場合は新しい受領単位へ保存し、
旧record_idとの訂正関係をレビューに残す。旧版と改訂版を独立した裏付けとして
数えない。重複や同じ原典の別主張を独立資料として数えない。

## 採用の意味

`accepted.jsonl` は抽出用資料の登録結果である。利用時は対応する
`manifest.json` と、存在する場合は `reviews.jsonl` も読む。収集者が付けた `verified` は
WorldModelの採用状態や真実性の保証ではない。

第4バッチ以降、ユーザーから追加の内容評価を依頼されない限り、採点・原典調査は
行わずに蓄積する。JSONの形式とrecord_idの重複だけを確認し、原本を保持する。
manifestにはユーザー指示による登録と評価未実施を明記し、架空の点数やレビューを
付けない。過去に保留した行の判定は変更しない。

入力文、引用、著者報告という位置付け、時点、地域、条件・例外、レビュー所見を
一緒に渡す。自然言語の条件をLLMが解釈し、既存の契約で検証する。
Grok独自のcombinatorや規則文字列をそのまま実行しない。
SourceRef、権限・scope、rootEvidenceId等は既存のホスト契約から与える。
seed試験ではMemory公開型のSourceRefでローカル文書を参照する。
外部原典の取得本文があるかのような参照や、独自の製品投入APIを作らない。

取得本文がなければ `original_source_snapshot: missing` と明示する。
インライン引用のハッシュ一致は、元の取得本文との一致を証明しない。
過去の取得本文・引用位置の再現が必要な用途には、そのまま使用しない。
再取得した本文は新しい取得時点の資料として保存する。収集者が記録した本文
ハッシュと一致し、引用位置も一致すれば、同じ本文バイト列を再取得できたことは
確認できる。元の通信ログや取得時刻まで復元できたことにはしない。

## 保存と次回受領

`collections/` はGit追跡対象外。公開リポジトリへのpushで資料のバックアップや
配布を兼ねない。必要なバックアップは、このディレクトリ全体を非公開で保全する。
原典ごとの再配布条件は未確認のまま保持する。

次回はJSONLだけでなく、収集キットが参照する取得バイト列、抽出本文、取得ログ、
manifestも相対パスを保った一式で受け取る。原本と取得時刻・抽出方式を残し、
本文ハッシュと引用位置の検証を可能にする。
